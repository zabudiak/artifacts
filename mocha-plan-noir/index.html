Upgrading Mocha: the corrected plan

Fri 9 Oct 2026. Built from the first plan and a second review, then checked read-only against the workspace. All times are Dublin. People and companies are labelled, not named.

Verdict. The direction is right: fewer runs, cheap local reading, drafts only. The first plan was wrong in two places. It rebuilt reply detection that already runs in the cloud, and its owed list missed people and treated one proposal as ready to draft when it isn't.

01What to keep

  • Fewer routine runs, plus an "already pinged" ledger of thread and event IDs so nothing is reported twice.
  • Heavy reading on the Mac with Haiku, writing one short report. Mocha checks any claim against its source before acting on it.
  • Drafts only. No booking, no Instantly writes, no new connectors, no extra bot layer, no server.
  • No paid lookups without a yes for that specific run.
  • Call packs from the existing sales playbooks folder (call framework v2, discovery playbook, call cockpit, ICP notes). The files exist.
  • A people key matched on email address, never on first name alone. The workspace has several first-name clashes.

02What to cut

The new Unibox reader cut

The hot-reply watcher already does this. It runs on Modal off Instantly reply webhooks, checks at 5, 15, 30 and 60 seconds, then again at 2 to 30 minutes for late labels. It posts each new Interested reply to the internal Discord hot-replies channel and to the client's own Slack or Chat. A Mocha poll of Instantly would duplicate all of it. Mocha reads the watcher's Discord channel instead.

"The Follow Ups gate is the only send path" wrong

Since 3 Oct the watcher auto-sends replies that pass a separate readiness check, for the house account and two client accounts, behind its own switch. Mocha must know this so it doesn't flag those replies as unanswered or draft a second reply.

The roster drift check as a new Haiku job cut

_state/ATTENTION.md is regenerated daily and already flags the stale draft batch (29 days) and two clients with no local movement. The Friday wrap reads that file and the roster's own "conflict" notes. Zaid edits the roster. Mocha never does.

Drafting proposals from Proposal gen defaults cut

Terms agreed on recent calls differ from the defaults and from each other. A draft uses the terms said on that prospect's call, from the transcript, and leaves a gap marked where a term is open.

04Top three changes, in order

Cut runs and stop duplicate pings

Inbox watch drops to four runs a day (08:30, 12:30, 17:30, 21:30) and stays silent unless something is new. Meeting prep becomes the morning brief plus one run about 90 minutes before each call. Inbox watch reads the hot-reply Discord channel rather than Instantly, and the pinged ledger filters out anything already posted there or auto-sent. Biggest cost drop, and it ends the repeat pings from three systems reporting the same reply.

One owed list with deadlines

The Monday pipeline review and Follow-ups show the list above as one view: who, what, deadline, source. Proposals are drafted only after Zaid answers that prospect's open questions, using terms from that prospect's transcript. Fathom transcripts only, never Fathom summaries. Mocha hands over a draft. Zaid sends.

Heavy reading through one fixed, read-only script

One script on the Mac with a fixed set of read-only calls, run by Haiku, writing one report. Haiku never writes its own Python against the Instantly helper. Spot-check each report against the source before anything from it lands in a ping or a draft.

05Risks

  • Tool limits. A Haiku run limited to Read, Glob and Grep can't execute Python, so it can't call the Instantly helper. That's another reason to use one fixed script rather than ad hoc calls.
  • Read-only by convention only. The Instantly helper's send function is disabled, but its internal request function can still send POST requests. Only the fixed script may import it.
  • Approval prompts block schedules. If every Mac call asks for approval, the four scheduled runs can't run unattended. Pre-approve the one script and nothing else.
  • Silent misses. If the Mac is asleep, a run is skipped and nobody hears about it. Mocha pings Zaid when a run fails or doesn't happen.
  • Haiku gets things wrong. It already reported two working launchd jobs as broken because it missed that their paths are symlinks. Treat its output as leads, not facts.
  • The watcher's blind spot. It reports Interested replies only. A question reply without that label, like Prospect H's, needs a direct Unibox check.
  • Back-to-back calls on Tue 13 Oct (20:00 and 20:30). One combined prep run before 18:30 covers both.
